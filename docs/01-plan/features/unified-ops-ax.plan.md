# Unified Ops AX — 전사 통합 운영체계 기획서 (Plan)

- **Feature**: `unified-ops-ax`
- **작성일**: 2026-07-30
- **대상 조직**: 소규모 제조/판매업 (~50인)
- **구축 전략**: 하이브리드 (핵심 데이터 허브 자체 구축 + 성숙 영역 SaaS 연동)
- **PDCA Phase**: Plan
- **상위 목표**: 부서별로 흩어진 업무 흐름·데이터를 하나의 운영체계로 통합하여 유기적·효율적으로 동작시킨다.

---

## 1. 문제 정의 (Why)

현재 상태(As-Is)의 핵심 통증:

| # | 통증 | 근본 원인 |
|---|------|-----------|
| P1 | 데이터 사일로 | 마케팅·CRM·공정·회계·일정이 각각 다른 도구/엑셀에 흩어져 단일 진실(SSOT) 부재 |
| P2 | 수작업 이관 | 부서 간 인계가 사람 손·구두·메신저로 이뤄져 누락·지연·오류 발생 |
| P3 | 맥락 단절 | 고객 1명의 여정(리드→주문→제작→납품→AS→재구매)이 한 화면에서 안 보임 |
| P4 | 지식 휘발 | 담당자 머릿속 암묵지가 기록되지 않아 이직·부재 시 손실 |
| P5 | 성과 불투명 | 개인/팀 성과가 사후 수기 집계, 실시간·객관 지표 부재 |
| P6 | 도구 과잉 | 사람마다 필요한 정보가 다른데 UX가 획일적 → 낮은 정착률 |

> **AX vs DX 구분**: 단순 전산화(DX)를 넘어, 이벤트 스트림 위에서 AI 에이전트가 지식화·팔로업·인사이트를 **자동 생성**하는 것이 본 프로젝트의 AX 지점.

---

## 2. 목표 & 성공 지표 (What / KPI)

### 정성 목표
- 모든 부서 데이터가 **하나의 표준 모델**로 흐른다 (SSOT).
- 부서 간 인계가 **이벤트 자동 전파**로 대체된다 (수작업 이관 제거).
- 각 인원은 **자기 업무에 맞춘 워크스페이스** 하나만 보면 된다.

### 정량 KPI (12개월)

| 지표 | 현재(추정) | 목표 |
|------|-----------|------|
| 부서 간 정보 재입력 횟수 | 건당 3~5회 | 1회 (SSOT) |
| 고객 이슈 응답 리드타임 | 실측 필요 | -50% |
| 지식 기록 커버리지 | ~0% | 핵심 업무 80% |
| 주간 성과 집계 소요 | 수시간(수기) | 실시간 대시보드 |
| 시스템 일 활성 사용률(DAU/직원) | - | 70%+ |
| 회계-주문-재고 데이터 정합성 | - | 99%+ |

> 착수 전 P0에서 현재값 실측(baseline) → 개선율은 실측 대비로 산정.

## 3. 범위 (Scope)

### 통합 대상 도메인 (11개) 및 Build vs SaaS 전략

| 도메인 | 전략 | 근거 |
|--------|------|------|
| 마케팅 (리드/캠페인) | **자체 허브 + 광고 SaaS 연동** | 리드-매출 연결이 핵심자산, 데이터는 자체 보유 |
| CRM (고객/영업) | **자체 허브** | 고객 360°는 SSOT의 심장, 커스텀 필수 |
| 제품 제작 공정 | **자체 허브** | 제조업 고유 공정, 표준 SaaS 부적합 |
| 제품 관리 (SKU/BOM/재고) | **자체 허브** | 공정·주문과 강결합 |
| 후속 팔로업 | **자체 허브 + AI 에이전트** | 이벤트 기반 자동화의 핵심 AX 영역 |
| AS (사후 서비스) | **자체 허브 + AI 에이전트** | 고객 여정과 강결합, 티켓 자동 분류 |
| 개인 성과관리 | **자체 허브 (파생 뷰)** | 이벤트 스트림에서 자동 산출 |
| 지식화 기록 | **자체 허브 + AI 에이전트** | 활동→지식 자동 캡처가 AX 차별점 |
| 개인별 커스텀 UX | **자체 구축 (경험 레이어)** | 역할별 워크스페이스, 정착률 좌우 |
| 회계 | **SaaS 연동** | 세무·법규 성숙 SaaS 사용 (더존/영림원 등), 이벤트만 동기화 |
| 일정관리 | **SaaS 연동** | Google/MS Calendar 연동, 자체 구축 낭비 |

### 명시적 제외 (Out of Scope, v1)
- 커스텀 회계/세무 엔진 자체 개발 (SaaS 위임)
- 하드웨어 IoT/설비 직접 제어 (공정은 데이터 기록까지, 제어는 향후)
- 마이크로서비스/K8s (50인 규모엔 과잉, 모듈러 모놀리스로)

## 4. 핵심 설계 원칙

1. **Single Source of Truth**: 모든 도메인은 하나의 표준 데이터 모델로 수렴. 중복 저장 금지, 파생은 뷰로.
2. **Event-first**: 부서 행위는 모두 원자 이벤트(Activity)로 기록 → 인계·성과·회계·지식화가 이 스트림의 파생.
3. **Customer & Employee 축**: 모든 이벤트는 고객·직원·제품에 앵커링 → 360° 뷰 자연 도출.
4. **하이브리드 통합**: 성숙 영역(회계/일정)은 사지 말고 연결. MCP/API를 표준 연동 프로토콜로.
5. **AI는 레이어**: 에이전트는 데이터 허브 위 별도 레이어. 데이터 없이 AI 없다 → 허브 먼저.
6. **역할별 경험**: 같은 데이터, 다른 창. 워크스페이스는 역할·개인 설정으로 조립.
7. **점진 도입(Crawl-Walk-Run)**: 빅뱅 금지. 도메인 1~2개로 가치 증명 후 확산.

## 5. 단계별 로드맵 (Phased Roadmap)

> 소규모 조직 현실 반영: 병렬 최소화, 각 Phase가 독립적 가치 산출(정착 우선).

| Phase | 기간 | 목표 | 핵심 산출물 | Gate(다음 단계 조건) |
|-------|------|------|------------|---------------------|
| **P0 진단·기반** | W1–4 | 현황 실측, 표준 모델·거버넌스 확정 | 데이터 감사, 표준 엔티티 모델, RBAC 정책, baseline KPI | 표준 모델 승인 |
| **P1 데이터 허브 MVP** | M2–3 | CRM+주문+공정 통합 SSOT | Postgres 허브, 코어 엔티티 CRUD, 고객 360° 뷰 | 실데이터 이행 완료 |
| **P2 SaaS 오케스트레이션** | M3–4 | 회계·일정 양방향 동기화 | 회계 커넥터, 캘린더 동기화, 이벤트 버스 | 정합성 99% 검증 |
| **P3 AI 에이전트 레이어** | M4–6 | 지식화·자동 팔로업·AS 분류 | 지식 캡처 에이전트, 팔로업 에이전트, AS 트리아지 | 에이전트 정확도 합격선 |
| **P4 경험 레이어·성과** | M5–7 | 역할별 워크스페이스, 실시간 성과 | 커스텀 UX 프레임, 성과 대시보드 | DAU 목표 도달 |
| **P5 확산·정착** | M7+ | 전 부서 확산, 거버넌스 정착 | 운영 런북, 채택 지표, 개선 루프 | 지속 운영 |

> P1~P4 상세 컴포넌트·데이터모델·시퀀스는 `docs/02-design/features/unified-ops-ax.design.md` 참조.

## 7. 즉시 착수 항목 (Next Actions — P0)

1. **데이터 감사**: 현재 쓰는 도구·엑셀·수기 목록화, 도메인별 데이터 위치 지도.
2. **표준 엔티티 모델 확정**: 설계서의 캐노니컬 모델을 실제 필드로 구체화(현업 인터뷰).
3. **baseline KPI 실측**: §2 표의 "현재값" 채우기.
4. **회계/일정 SaaS 확정**: 현재 사용 중인 회계 SW·캘린더 파악 → 연동 방식 결정.
5. **파일럿 도메인 선정**: 가장 통증 큰 1~2개(권장: CRM+주문) 우선.
